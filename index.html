The time our live app broke

We deployed the placement app to Render as two services, one for the front end and one for the back end. Then the live version stopped working.

It turned out to be three problems at once. The TypeScript build was failing, the front end had the wrong server address baked into it, and our CORS setup (the rules for which websites are allowed to talk to the server) was too loose. I fixed the build, corrected the address, and replaced the CORS setup with a strict list of allowed addresses for both the normal API and the live chat.

// only let our own front end talk to the server
const allowed = [process.env.FRONTEND_URL];

app.use(cors({ origin: allowed }));
const io = new Server(server, { cors: { origin: allowed } });
a simplified version of the fix

Another one I was glad I caught: while reviewing a teammate's code I noticed the login route had no error handler. If the database had gone down, login would have just failed silently. Small fix, but that kind of bug is a pain to track down later.
